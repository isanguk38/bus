# 🚌 버스 지금 어디

전국 시내버스의 실시간 위치를 **지도 위에서 실제로 움직이는 모습**으로 보여주는 웹 서비스입니다.

기존 지도 앱은 버스 위치를 노선도 위 아이콘으로만 보여줍니다. 이 서비스는 공공 API의 느린 갱신 주기(20~30초)를 보간과 예측으로 메워, 버스가 도로를 따라 부드럽게 다가오는 모습을 보여줍니다.

## 사용 흐름

```
노선 검색 (지역은 내 위치로 자동 선택) → 노선 실시간 지도
  └ 어디서 타세요?  [📍 내 주변 정류장 보기] 또는 [정류장·상가 이름 검색] 또는 지도에서 정류장 선택
                    → 이 노선이 서는 정류장을 가까운 순으로 → 고르면 "여기서 탑승"
  └ 내 정류장으로 오는 버스만 지도에 남기고, 도착 예상 시간·남은 정류장 수 표시
```

## 주요 기능

- **탈 곳 정하기**: 내 위치(또는 지도 가운데) 주변의 이 노선 정류장을 거리·도보 시간·방면과 함께 목록으로 보여주고 직접 선택. 정류장 이름이나 상가·건물 이름(카카오/브이월드 키 설정 시)으로 찾으면 그 근처의 이 노선 정류장으로 연결
- **방향별 색**: 노선 선과 버스 아이콘을 가는 길/오는 길 색으로 구분, 내 정류장 방향을 고르면 그 방향 선과 나에게 오는 버스만 표시
- **내 정류장으로 오는 버스**: 노선 화면에서 내가 탈 정류장까지 남은 시간·정류장 수를 직접 계산해 표시. 길 건너편 정류장은 "OO 방면"으로 골라 선택, 이미 지나간 버스는 흐리게
- **전국 지원**: 서울(서울시 API)과 그 외 138개 시·군(국토교통부 TAGO API, 경기도 포함)
- **도로를 따라 움직이는 애니메이션**: 버스가 건물을 가로지르지 않고 노선 경로 위로 이동
- **위치 예측**: 다음 데이터가 오기 전까지 추정 속도로 앞으로 나아가고, 새 데이터가 오면 자연스럽게 보정
- **원본 GPS 비교 보기**: 보정 전 원본 위치를 함께 표시해 보간 효과를 확인
- **공유 가능한 URL**: `?region=seoul&route=100100447&no=7016`
- 저상버스·혼잡도 표시(서울), 다크 모드, 모바일 화면 대응

## 구조

```
브라우저 ──(SSE)── Express 서버 ──┬── 서울시 버스 API
  Leaflet 지도                      └── 국토교통부 TAGO API (전국)
  위치 보간 · 예측
```

| 경로 | 역할 |
|---|---|
| `server/providers/` | 지역별 API를 같은 형태로 바꾸는 어댑터 (`seoul.js`, `tago.js`) |
| `server/live-hub.js` | 노선별 실시간 채널. 보는 사람이 있는 노선만 수집하고, 결과를 모든 구독자에게 나눠줌 |
| `server/lib/quota.js` | API별 일일 호출 한도를 세고, 넘기 전에 수집을 멈춤 |
| `server/lib/cache.js` | 노선·정류장 같은 정적 정보 캐시 (동시 요청 합치기 포함) |
| `public/js/geometry.js` | 위경도 ↔ "경로 위 거리" 변환 |
| `public/js/tracker.js` | 버스 한 대의 속도 추정과 화면 위치 계산 |
| `public/js/eta.js` | 내 정류장으로 다가오는 버스와 예상 도착 시간 |
| `public/js/app.js` | 지도, 검색, 실시간 연결, 애니메이션 루프 |

## 기술적으로 해결한 문제

### 1. 갱신이 느린 데이터를 부드럽게 보여주기
공공 API 위치는 20~30초마다 한 번씩 갱신되고, 받는 시점에도 이미 수 초~수십 초 지난 값입니다.

- 버스 위치를 위경도가 아니라 **노선 경로 위의 거리(m)** 로 바꿔서 다룹니다. 애니메이션은 거리를 늘려가기만 하면 되고, 그릴 때 다시 좌표로 바꾸기 때문에 항상 도로 위를 지나갑니다.
- 연속된 두 관측으로 속도를 추정하고, 다음 관측 전까지 **추측 항법**으로 앞으로 나아갑니다.
- 예측이 실제보다 앞서면 뒤로 되돌리지 않고 실제 위치가 따라올 때까지 기다립니다. 크게 어긋날 때만 즉시 이동합니다.
- 측정 시각(`dataTm`)을 기준으로 계산하고, 서버와 브라우저의 시계 차이도 보정합니다.

### 2. 왕복 노선에서 버스가 반대편 차선에 붙는 문제
같은 도로를 오가는 노선은 가장 가까운 지점만 찾으면 반대 방향 경로에 붙습니다. API가 주는 **정류장 순번으로 탐색 구간을 좁혀서** 올바른 방향에 붙도록 했습니다.

### 3. 일일 호출 한도 (서울 1,000회 / TAGO 10,000회)
- 사용자마다 API를 부르지 않고, **서버가 노선별로 한 번만 수집해 SSE로 나눠줍니다.**
- **보는 사람이 있는 노선만** 수집하고, 새로고침해도 수집 주기는 유지됩니다.
- 브라우저 탭이 1분 이상 가려지면 연결을 끊습니다.
- 노선·정류장 정보는 24시간 캐시합니다.
- 서버가 호출 수를 직접 세서 한도에 닿기 전에 멈추고 사용자에게 알립니다.

### 4. 서로 다른 API 통합
서울 API와 TAGO는 응답 형식, 좌표 필드, 결과 0·1건일 때의 표현이 모두 다릅니다. 지역별 어댑터가 같은 형태로 바꿔서 나머지 코드는 데이터 출처를 신경 쓰지 않습니다.
(경기도 버스위치 API는 GPS 좌표 없이 정류장 순번만 제공해서, 좌표를 주는 TAGO로 경기도를 처리합니다.)

### 5. 내 정류장까지 도착 예정 시간 직접 계산
노선 화면은 도착 정보 API를 추가로 부르지 않고, 이미 받은 버스 위치로 예상 시간을 계산합니다.
- 버스와 내 정류장 모두 "경로 위 거리"로 바꾸면, 다가오는 버스 = 내 정류장보다 뒤에 있는 버스, 남은 거리 = 두 거리의 차
- 버스 한 대의 순간 속도는 정차·신호로 들쭉날쭉해서 **노선 전체 버스 속도의 중앙값**을 평균 속도로 사용
- 공식 도착 정보와 비교: 안양 10번 범계역 기준 공식 "1분·1정거장 전 / 14분·8정거장 전" ↔ 계산값 "약 2분·1정거장 전 / 약 13분·8정거장 전"
- 왕복 노선의 방향은 상·하행 정보가 있으면 그대로, 없으면 출발점에서 가장 먼 정류장을 반환점으로 보고 나눔

### 6. 갱신이 드문 데이터에서 버스가 멈췄다 튀는 문제
5초 간격으로 90초 동안 측정해 보니 실제 위치가 바뀌는 간격이 서울은 약 11초, TAGO는 약 42초였습니다.
TAGO를 20초마다 수집하면 절반은 같은 위치가 다시 오는데, 이를 새 관측으로 보면 "멈췄다"고 판단해 화면의 버스를 세우고,
다음에 위치가 바뀌면 밀린 거리를 1~2초 만에 따라잡느라 튀어 보였습니다.
- 서버가 차량별로 **위치가 처음 바뀐 시각**을 기억해 관측 시각으로 사용 → 같은 위치는 새 관측으로 치지 않음
- 화면 버스는 12초 뒤 예측 지점을 목표로 **속도를 서서히 조절**(가속도·최대 72km/h 제한)하고, 예측은 추정 속도의 0.8배로 보수적으로 잡음
- 실시간 데이터 3분을 녹화해 설정 조합을 비교: 화면 최대 속도 216 → 72km/h, 달리는 버스가 멈춰 보이는 비율 32% → 9%
- API 호출 횟수는 그대로

### 7. 도로 경로가 없는 지역의 경로 복원
TAGO는 정류장 좌표만 주기 때문에 정류장을 직선으로 이으면 선과 버스가 건물을 가로지릅니다.
정류장 사이를 **OSRM(OpenStreetMap 기반 경로 탐색)** 으로 실제 도로에 맞춰 잇습니다.
- 공개 서버 이용 정책(초당 1회)에 맞춰 25개 정류장씩 나눠 요청하고, 결과는 24시간 캐시
- 일방통행·유턴 때문에 직선보다 3배 이상 돌아가는 구간은 잘못된 경로로 보고 직선으로 대체
- 실패해도 직선 경로로 동작 (서비스가 멈추지 않음)

## 로컬 실행

Node.js 20.12 이상이 필요합니다.

```bash
npm install
cp .env.example .env   # DATA_GO_KR_SERVICE_KEY에 공공데이터포털 인증키 입력
npm run dev            # http://localhost:3000
npm test               # 단위 테스트
```

### 필요한 공공데이터포털 API (모두 무료, 자동 승인)
- 국토교통부_(TAGO)_버스위치정보
- 국토교통부_(TAGO)_버스노선정보
- 서울특별시_버스위치정보조회 서비스
- 서울특별시_노선정보조회 서비스
- 국토교통부_(TAGO)_버스정류소정보
- 국토교통부_(TAGO)_버스도착정보
- 서울특별시_정류소정보조회 서비스

## 배포 (Render)

1. Render 대시보드 → **New → Blueprint** → 이 저장소 연결 (`render.yaml` 자동 인식)
2. 환경 변수 `DATA_GO_KR_SERVICE_KEY`에 인증키 입력
3. 배포 완료 후 `https://<서비스명>.onrender.com` 접속

무료 플랜은 15분간 요청이 없으면 서버가 잠들어 첫 접속이 30초가량 느릴 수 있습니다.

## 선택 환경 변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `SEOUL_POLL_MS` | 30000 | 서울 버스 위치 수집 주기 (ms) |
| `TAGO_POLL_MS` | 20000 | TAGO 버스 위치 수집 주기 (ms) |
| `SEOUL_DAILY_LIMIT` | 1000 | 서울 API 일일 호출 한도 |
| `TAGO_DAILY_LIMIT` | 10000 | TAGO API 일일 호출 한도 |
| `OSRM_URL` | https://router.project-osrm.org | 도로 경로 탐색 서버 |
| `KAKAO_REST_API_KEY` | (없음) | 카카오 로컬 API 키. 상가·건물 이름으로 장소를 찾아 주변 정류장 검색 (브이월드보다 우선) |
| `VWORLD_API_KEY` | (없음) | 브이월드 배경지도·장소 검색 키. 없으면 OpenStreetMap 지도 + 정류장 이름 검색 |
| `VWORLD_DOMAIN` | (없음) | 브이월드 키 발급 시 등록한 서비스 URL |
